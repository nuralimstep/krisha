# Krisha → Telegram на FastAPI

Отслеживает однокомнатные квартиры в Алматы за **100 000–150 000 ₸/месяц**.
Проверяет первые 3 страницы выдачи с сортировкой по дате каждые 60 секунд.
Отправляет подходящие новые объявления в один личный Telegram-чат.

## Что считается подходящим

- Отдельная однокомнатная квартира, Алматы, помесячная аренда, бюджет включительно.
- От 20 м² и с фото. Параметры настраиваются в `.env`.
- В тексте карточки нет явного подселения, койко-места, общежития, посуточной аренды.
- `OWNERS_ONLY=true` оставляет только объявления с отметкой собственника.

Это фильтрация по доступной карточке, а не проверка состояния квартиры, честности автора
или полной стоимости с депозитом/комиссией. Описание в выдаче бывает сокращённым.
При первом запуске отправляются максимум 5 подходящих вариантов; остальные отмечаются
просмотренными. Далее отправляется каждое впервые обнаруженное подходящее объявление.
`/latest` показывает до 5 вариантов из последней успешной проверки.

## Неактуальные квартиры

Бот сохраняет ID каждого отправленного объявления и его сообщений в Telegram, включая
копии из `/latest`. Ранее найденные варианты периодически проверяются по прямым ссылкам:
`AVAILABILITY_INTERVAL_SECONDS=300` задаёт минимальный интервал между попытками проверки
одной квартиры, `AVAILABILITY_BATCH_SIZE=20` — максимум объявлений за цикл. Пауза между
запросами — секунда; обход очереди начинается каждый `POLL_INTERVAL_SECONDS` после предыдущего.

При HTTP 404/410, подтверждённой отметке архива или прямом сообщении «квартира сдана»
вариант исключается из списка, а сохранённые сообщения удаляются. Бот также учитывает
отметку «сдана» в тексте поисковой карточки. Исчезновение с первых страниц поиска,
403/429, таймаут, редирект и неизвестная разметка не считаются подтверждением сдачи квартиры.
При ошибке отдельной страницы проверка останавливает текущую пачку и делает паузу перед повтором;
ошибка видна в `GET /status` (`availability_error`) и в команде `/status`.

Если собственник оставил объявление активным после сдачи, автоматически узнать о заселении
невозможно. Нажмите **«Уже сдали»** под сообщением бота: вариант будет скрыт, все сохранённые
копии его сообщений убраны. Кнопка доступна только привязанному владельцу личного чата.
Неактуальная квартира с тем же ID не появится снова после новой проверки или перезапуска.
История в базе сохраняется для защиты от повторных уведомлений.

[Telegram позволяет удалять сообщения только в течение 48 часов](https://core.telegram.org/bots/api#deletemessage).
Для более старых сообщений бот заменяет карточку отметкой «Объявление больше неактуально».
Ошибки удаления повторяются с учётом `retry_after`; уже удалённые сообщения обрабатываются повторно безопасно.
Уборка продолжается при `/stop`, который приостанавливает только новые уведомления.
Сообщения прежней версии, отправленные без сохранения `message_id`, автоматически убрать нельзя.

## Запуск

```bash
python3 scripts/setup_env.py
```

В `.env` добавьте `TELEGRAM_BOT_TOKEN` от [@BotFather](https://t.me/BotFather).
Скрипт уже сгенерирует `ADMIN_TOKEN` и `BOT_ACCESS_CODE`. Не публикуйте `.env`.
Запустите сервер, откройте своего бота и отправьте `/start <BOT_ACCESS_CODE>`.
Можно вместо кода задать свой числовой `TELEGRAM_CHAT_ID`, но сначала всё равно
нужно открыть бота и нажать Start: бот не может первым начать личный диалог.

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/uvicorn app.main:app --host 127.0.0.1 --port 8000 --workers 1
```

Без токена работает проверка Krisha и API, но уведомления не отправляются.
После изменения `.env` перезапустите процесс.

## Деплой на VPS с Docker

Скопируйте проект на сервер, создайте и заполните `.env`, затем:

```bash
docker compose up -d --build
docker compose ps
docker compose logs --tail=100 tracker
curl --fail http://127.0.0.1:8000/health
```

Домен и публичный порт для Telegram не нужны: используется long polling.
API привязан к `127.0.0.1:8000`. Для удалённого доступа используйте SSH-туннель
или существующий reverse proxy с HTTPS. SQLite находится в Docker volume `tracker-data`:
не удаляйте его при обновлении. Для обновления снова выполните `docker compose up -d --build`.
Docker запускает контейнер после перезагрузки, если Docker daemon включён в автозапуск.

Запускайте **один экземпляр / один worker**, чтобы не создавать конкурирующие Telegram
polling-процессы и повторные уведомления. Нужен постоянно работающий сервер с диском;
хостинг, засыпающий между HTTP-запросами, для такого фонового процесса не подходит.

## Команды и API

- `/start <код>` — первая привязка; `/start` — возобновление после паузы.
- `/stop` — приостановить отправку уведомлений.
- `/status` — время последней проверки и состояние поиска.
- `/latest` — до 5 последних подходящих квартир.
- «Уже сдали» под квартирой — убрать неактуальный вариант и связанные сообщения.
- `GET /health` — процесс и фоновые задачи работают. Успех не означает доступность Krisha/Telegram.
- `GET /status` — фильтры, последняя успешная проверка и ошибки интеграций.
- `GET /listings?limit=20` — подходящие объявления последней проверки.
- `POST /check` — ручная проверка.

Последние три API требуют `Authorization: Bearer <ADMIN_TOKEN>`.
Не помещайте секрет в URL. Swagger отключён.

При временной ошибке Telegram сообщение остаётся в очереди; учитывается `retry_after`.
История и очередь переживают перезапуск. Доставка выполняется с подтверждением Telegram:
редкий сбой между отправкой и записью подтверждения может привести к повтору.
При 403/429/CAPTCHA Krisha бот фиксирует ошибку и увеличивает интервал повторов,
не пытаясь обходить блокировку. Нормальная задержка — до интервала проверки плюс время
сети; охват ограничен `SEARCH_PAGES`. Мгновенная доставка и полнота выдачи не гарантируются.

## Проверки

```bash
.venv/bin/pip install -r requirements-dev.txt
.venv/bin/python -m pytest -q
.venv/bin/ruff check .
```

Тесты проверяют фильтры, парсеры выдачи и доступности, защиту чата/API и кнопок,
очередь после сбоя Telegram, удаление и пометку старых сообщений,
сохранение истории после перезапуска и корректное завершение фоновых задач.
